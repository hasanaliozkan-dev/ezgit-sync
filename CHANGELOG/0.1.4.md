## ezgit-sync 0.1.4

### Fixed

- Local changes are committed before pulling, and pulling uses `git pull --rebase`, so edits that touch the same files as a teammate's no longer stop the sync, and diverged branches are reconciled.
- Commits left behind by a failed push are pushed on the next run instead of being reported as "no changes".
- New branches that don't exist on origin yet can be synced (they are created by the push).
- A conflicting rebase is aborted, leaving your work committed locally, with steps to resolve it.
- Git's own error output (hooks, identity problems) is shown when a commit fails, and every error is reported once.
- A clear message when Git is not installed, instead of a traceback.
- `python -m ezgit_sync` returns a non-zero exit code on failure.
- The branch name in pull error messages, and the default commit message ("Auto-sync via ezgit-sync") now match the docs.
- Colors are only used on a terminal and respect `NO_COLOR`.

### Changed

- Package renamed to `ezgit_sync` and packaging fixed so the wheel and the `ezgit-sync` command work.
- Supports Python 3.10+; CI tests 3.10–3.14.
- No runtime dependencies (unused `typer` and `rich` removed).
- New helpers: `commit_local_changes`, `push_changes`, `has_unpushed_commits`.
